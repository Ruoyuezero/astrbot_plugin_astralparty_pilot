## 二、筹码（relic）

### 2.1 按定位选筹码

| 定位 | 主要筹码类型 | 典型筹码 |
|---|---|---|
| 物理输出 | 攻击型 | 拳套、美工刀、肾刀、瞄具 |
| 法系输出 | 出牌型 | 大背包、书签、飞镖、可口糖果、法杖、喷罐 |
| 辅助 | 辅助型 | 徽章、炖肉、银行卡、头盔、饼干 |

### 2.2 分系规则（硬约束）

- 筹码分**通用系** + 四个系：治愈系、标记系、星光系、充能系。
- 只能拿**通用系 + 其中两系**。
- 一旦拿到两种不同系，剩下两类就再也拿不到 —— 这就是**筹码分系**。
- 常规选择：
  - 输出型 → 治愈系 + 标记系
  - 辅助型 → 星光系 + 治愈系
  - 充能系一般只在高难图用，此时输出可以选充能系

### 2.3 系强度

治愈系 > 标记系 ≈ 星光系 > 充能系

> 充能系偏生存，伤害最低；治愈系伤害高于标记系。

### 2.4 必拿系（角色定了就必须走这个系）

| 系 | 必须拿的角色 |
|---|---|
| 标记系 | 121、127 |
| 星光系（钱辅：给主 C 转账，拿到飞星后路过怪物一路放过即可造成伤害） | 101、102、108、114、305 |
| 治愈系 | 112、123、302、304 |

## 三、升星与金币

| 星 | 花费（星币） |
|---|---|
| 1 星 | 15 |
| 2 星 | 20 |
| 3 星 | 25 |

- 输出型角色**优先升星**，达到 2 星后才允许买筹码。
- 但大多数情况还是优先冲 3 星。
- 星级越高，开出好筹码的概率越高。
- 地图任务给筹码，**优先完成任务**提升实力。
- 攻击力足够高就可以去打 BOSS，击败即胜利。

## 四、买牌逻辑

### 4.1 输出型

- 0 星且金币低于 18 → **禁止买牌**。
- 达到 1 星后可以买牌，主要买攻击牌。
- 攻击牌超过 4 张后，不再买普通攻击牌（费用 < 4 的），但可以买 **嘎呜切、蓄力**（费用 > 3 的高级攻击牌）。

### 4.2 辅助型

- 优先把金币转给输出型角色，帮其升星。
- **不可以随意买牌。**

## 五、战斗逻辑

### 5.1 攻击

1. 若 `攻击力 > 该怪防御力 + 生命值` → 直接攻击。
2. 否则判断该怪会不会反击：
   - 不会反击 → 直接打。
   - 会反击 → 看手里有没有攻击牌，若 `攻击力 + 可出攻击牌期望伤害 > 怪防御 + 生命值` → 打；否则放过。
3. **打小偷不使用攻击牌**（2026-11-04 主人口述）—— 小偷**直接点攻击就搞定**，不用出牌、不用垫伤害。

### 5.2 防御

1. 若 `怪物攻击力 < 自己防御值 + 2` → 不需要防御牌，直接防御。
2. 若 `怪物攻击力 > 自己防御值 + 2` → 需要防御牌，差值为 x，选防御牌使**期望防御达到 x**。

### 5.3 期望值算法

- 期望取牌面随机区间的**中值**。
- 可出牌的费用上限：1 星最高 4 费，之后每多一星 +1，3 星最高 6 费。
- 出牌时**优先消耗费用更低的牌**（同样的期望下，先烧便宜的）。
- 例：1 星，防御牌 1 费 ×2、2 费 ×2、3 费 ×1，可出费用上限 4。
  - 3 费 ×1 + 1 费 ×1 → 防御 2~13，期望 7.5
  - 2 费 ×2 → 防御 2~12，期望 7
  - 2 费 ×1 + 1 费 ×2 → 防御 3~12，期望 7.5 ← 优先这个（费用更低）
- 攻击牌同理。

### 5.4 卡牌费用表（2026-11-04 口述）

**效果牌统一 0 费**：加攻、加防、治愈、上标记这类效果牌本身不消耗费用，
出牌也不另外付出任何成本 —— 所以不存在「出不起」的问题，难点只在**什么时候用、用哪张**。

带费用的牌（逐个核过 `kb/cards.json`，`/app card <id>` 也能查）：

| 10002 | 防御(中) | 防御 | 1 | 防御力 +1~3 |
| 10003 | 攻击(大) | 攻击 | 2 | 攻击力 +1~6 |

- 10012 / 10013 只有真梦梓能出，别的人拿到也用不了。

### 5.5 免反击牌（10008 暗影突袭 / 10011 毒牙）的用法

这两张牌的价值不在伤害，而在**「本次攻击无法被反击」**这条：
- 10008 暗影突袭：2 费，攻击力 +3，本次攻击无法被反击。
- 10011 毒牙：2 费，移除目标 2 层【金鳞】，本次攻击无法被反击（龙宫游乐园、帮天川真梦梓时的专属牌）。

使用规则：
1. **只对「会反击」的怪物使用。** 打不会反击的怪用它们纯属浪费——免反击效果一文不值，伤害还不如普通攻击牌。
2. **要打会反击的怪，先看能不能 100% 击飞。**
   - 能保证一击击飞（我方攻击力 + 牌面最低伤害 ≥ 怪的防御 + 生命，取最坏情况）→ 直接按 5.1 打，不必绕道用免反击牌。
   - **不能 100% 击飞 → 用 10008**，靠「无法被反击」白吃这一次攻击，不挨反击伤害。
3. 10011 额外削 2 层金鳞，龙宫图遇到叠甲怪优先考虑它；但别的地图/别的角色没有这张，不要把判定写成「有 10011 就上」。
4. 判定口径统一按 5.3：取牌面**最坏情况**判断能否击飞，「大概能打死」不算 100%。

## 七、代码侧读取口径（2026-11-04 核实）

- **筹码 id ↔ 条目**：`kb/relics.json` 的 `no` 字段**就是**游戏内 id —— 例：50033 = 可口糖果（治愈系·紫）、50053 = 大铁锚、50036 = 「8面」骰子。`kb.relic(50033)` 直接拿 name / quality / faction；另有 `kb/relic_no_map.json` 共 90 条 id → 名称/图标/品质。候选下发的只有 id 也完全够选筹码。
- **星级**：局内 state 的 player 里有 `star`（旧版叫 `lv`），`pkg/livecard.py` 的局内卡就在读它；`/app <UID>` 查别人的局内卡走房间详情里的 hero 快照，同名字段。`pkg/coach.py` 的 `me` 白名单只挑了 hp/atk/def/gold 等 9 项，把 star 过滤掉了 —— 补进白名单即可用于升星门槛判定。

## 八、战斗界面读数补充（2026-11-04）

- **怪物属性只认 FIGHT 开场三图标**：❤ = 血量、剑 = 攻击、蓝盾 = 防御。
- 战斗页中间那条「ATTACK 8 - 8 / DEFENSE」**不是怪物防御值**，不要拿它当防御读，判定一律走 5.1 的式子。
- 实测例：我方攻击 8，鲨鱼图鉴 1 防 2 血 → 8 > 1+2，走 5.1 第一条「直接攻击」，不需要出牌。

## 九、陪玩命令逻辑（/appa buy · atk · def · dodge · skip · relic）

> **授权是叠加的**：`/appa card`、`/appa skill`、`/appa go` 连着发，三个授权会同时留着 ——
> 一个回合本来就是 出牌 → 技能 → 移动。`/appa on` 才是全覆盖，`/appa off` 清空全部。
> 动作类子命令都是**一次性**的：做成了静默不回话，**做不成会回一条说明 + 理由**
> （如 `/appa card` 手牌里没有能出的牌、`/appa buy` 不在商店、`/appa go` 不在移动阶段），
> 说明发出后这一项授权自动收回，要再来一次就再发一遍。等 8 秒还没动手也按「没做成」处理。

### 9.1 /appa buy —— 经过商店时：购买（2026-11-04 实测跑通）

界面构成：三张卡并排 + 下方「购买！-N」粉键 + 「返回」蓝键，右上「刷新 ×N」。

流程：
1. 逐张看牌名/费用/效果，按第四节 4.1 判「要不要买」。
   - 输出型：0 星且金币 < 18 → 不买；1 星后可买，优先攻击牌；攻击牌已 ≥ 4 张后只买嘎呜切、蓄力这类高费攻击牌。
   - 三张都不是目标（如全是回复/移动/防御）→ 商店**不能刷新**，直接点「返回」走人。
     （「刷新 ×N」只出现在「请选择一枚战斗筹码」界面，见 9.4；商店页没有这个键。）
2. 决定买哪张 → 点那张牌（选中后卡面出现蓝/绿框，购买键价格跟着变）→ 点「购买！」。
3. 成功后该卡位变 **SOLD OUT**，金币减少，牌进右下角手牌；其余两张仍在，可继续买或直接返回。
4. 点「返回」离开商店；返回后常紧接着弹事件卡（如 NEWS-012「食品安全」），点一下就关掉，然后回到地图。
5. 实测记录：第 2 轮商店，金币 32，买到「操控骰子」3 费 → 金币 32→29，手牌变为 王之力 / 攻击（特大）/ 防御（中）/ 操控骰子。

要点：购买键位置别写死，扫粉色段算中心更稳（此前目测坐标点偏过一次）。

### 9.2 /appa atk —— 经过怪物时：攻击

- 触发时机：路过/停在怪物格时替玩家选择「迎战」。
- 打不打、要不要补牌，一律走 **5.1**：攻击力 > 敌方防御 + 敌方当前血量 → 直接打；打不穿才看手牌与是否反击。
- 怪物属性只认 FIGHT 开场 ❤/剑/蓝盾（见第八节），「ATTACK 8-8」不是防御值。

### 9.2b 站在怪物突击门（t=21）上：先选怪，再谈打不打（2026-11-05 口述）

- 判定：`map.json` 的 `lands` 里按 `state.players[].node` 找到当前格，`t == 21` 就是怪物突击门。
- 第一次 `/appa atk`：在突击界面上替你**选一只怪**（选中即传送到怪物格），然后弹出的 5047 才决定打不打。
- 再发一次 `/appa atk`：5047 选「打」。
- 改发 `/appa skip`：同样选怪传送过去，但 5047 选「放过」—— 只过去，不动手。
- 开打之后进战斗界面（FightWindow 在树里就算开着）：再发一次 `/appa atk` = 点那颗
  **READY / 攻击** 键（舞台 512,761）。这一步不看手牌，有 atk 就按，不会替主人挑战斗牌。
  整条链：站突击格 → `/appa atk` 选怪 → `/appa atk` 打（5047）→ `/appa atk` 点 READY 攻击。

### 9.2c /appa card 在战斗界面出战斗牌（2026-11-06 主人补）

- 战斗界面（UI 树里有 `FightWindow`）开着时，`/appa card` 也管战斗牌：
  挑一张手牌里能用的**攻击 / 防御**牌拖进战斗区（和效果牌一样拖到舞台中心）。
- 战斗里 `state` 的 `usable` 是**空的**，能出什么得自己算，判据全在 `state.fight` 里：
  - 谁是攻击方：`fight.attacker.pid == selfPid` 就只能出**攻击**牌，否则只能出**防御**牌
    （kb 里写明：攻击牌「战斗中攻击方可用」、防御牌「战斗中防御方可用」）
  - 费用：卡的 `cost` 不得超过 `fight.<我方>.cost`（本轮可用费），不够就跳过并说明
  - 同类型里先挑便宜的，再按卡号，保证一轮里挑法稳定
- 出完**不替你按 READY** —— 结算是 `/appa atk` 的事，节奏留给你。
- 拖拽判成功的口径：拖完轮询手牌最多 2.4 秒，只有「同卡号张数变少 / 总张数变少」才算出成；没变就是没拖上（战斗中手牌面板还在做动画时常见），引擎会隔 1.2 秒重试并把原因写进 `fight_note`。
- 授权优先级：`atk` 在场时先点 READY（"打小偷直接点攻击"的老路子不变），
  只有单独 `/appa card` 时才走这条出牌路径。
- 判定战斗界面带 1 秒缓存：导 UI 树贵，不能每帧导；离开战斗时顺手把旧原因清掉。
  - 2026-11-13 补充：战斗里 `uitree` 经常没回音，只认 `FightWindow` 会一直判成「不在战斗」。所以 `fight_open()` 增加**协议兜底**——`state.battle` 为真、`state.fight` 有攻防双方、`end=0`、且自己在其中一方、state 未过期（180 秒）时，直接算在战斗里。
  - 同场同键只按一次：按 `fight.battleId` 记账（`_fight_done`），避免「确定 / 防御」被每 1.5 秒连点；`/appa ok` 这类一次性授权不设限，发一次按一次。
- 没出成时异常说明直接给原因：`手牌里攻击牌费不够（攻击方可用 1 点）：《名刀：嘎呜切》4费`／
  `手上只有防御牌，这轮我是攻击方，用不上`／`《XX》没出成（拖进战斗区没生效）`。
- 选怪键的名字还没实测定死，引擎按 path 含 `Teleport / Assault / AttackGate / PK` 宽松匹配，
  名字含 `atk / attack / fight / pk / ok / confirm` 优先；一次都没认出来时日志里会打一行
  `[突击门] …（候选 …）`，把候选名念给它听就能定死。兜底坐标 `GATE_ATK_POS` 目前是 None（不点固定位置）。

### 9.3 /appa skip —— 只负责「放过 / 取消」（2026-11-13 主人定稿）

`skip` 只做四件事，四个界面各一件：

| 界面 | 点哪个键 |
|---|---|
| `fight_ask`（攻击选择页） | 放过 |
| `assault_pick`（突击页） | 取消 |
| `shop_card`（卡牌商店） | 取消 |
| `relic_buy`（筹码购买选择页） | 取消 |

- **不管出牌阶段**（不出牌请用 `/appa off` 或直接不出，别指望 skip 点取消）；
- **不管闪避**（闪避是 9.3b `/appa dodge`）；
- **不管买不买**（筹码买不买是 `/appa relicskip`，商店买不买是 `/appa buy` / `/appa buyskip`）。

### 9.3b /appa dodge —— 闪避

- 只管一件事：被怪物反击 / 怪物回合被攻击（协议 5039）时选**闪避**（dodge=true）。
- 只授 dodge 时，5047「是否开战」不替主人决定；atk 与 dodge 同时授权以 atk 为准（要打就别躲）。
- 防御与闪避的取舍代价待补。

### 9.4 /appa relic —— 战斗筹码三选一

- 只在「请选择一枚战斗筹码」界面动作，判定依据 2.2 分系：只拿通用系 + 目标两系。
- 输出型：治愈系 + 标记系；辅助型：星光系 + 治愈系。
- 三张都没踩到目标系 → 用右上「刷新」（最多 2 次）；仍无交集就挑收益最高的一张带走。

## 十二、授权机制：单次 / 常驻

单项授权（`/appa card`、`/appa skill`、`/appa go`、`/appa atk` …）是**调试单个动作**用的：

- 写进 `coach_ctl.json` 时带 `once` 清单，形如 `{"allow":["card","skill","go"],"once":["card","skill","go"]}`
- 引擎每帧读一次；替我做完其中某一下，就把那一项从 `allow` / `once` 里删掉、写回控制文件，
  日志记一条 `[授权收回] 出牌（单次动作已执行完）`
- 所以发一次 = 动一下，后面的回合不会自己接着动；要再来一次就再发一遍
- 多项一起发是「叠加」：做完出牌收回出牌，技能/移动那两项还留着，按顺序一项项消耗
- `/appa on` 走全覆盖（FULL_ALLOW）且**不带 once**，那才是常驻；`/appa off` 清空并停进程

引擎侧实现：`Coach.once` + `_consume_acted()`，由 `tick()` 在每帧结束后统一结算
（用 `acted.what` 关键字映射回动作类别，映射表 `_WHAT_KIND`）。


## 十三、出牌评分：阈值 + PVE 血线分层（2026-11-05 主人定）

### 13.1 出牌阈值
- `PLAY_MIN = 2.5`：评分不到 2.5 一律 pass，不为了「把牌打出去」而打。

### 13.2 骰子 / 改点类牌（遥控骰子 20005、名字含「骰 / 命运 / 方向」）

## 十六、动态表情（VEmoji 序列图）

部分表情在游戏里是动的，资产是**一张序列图**而不是 GIF：

- 文件：`misc/VEmoji_<英雄ID>_<表情序号>.png`（`/app load` 会一起解出来）
- 排版：每格 **168×168**（160 画面 + 4px 内边距，对应着色器 `_FramePaddingPixels=4`），
  帧**从左到右、从上到下**排，末尾空格子只是补齐成矩形
- 播放：由 `Unlit/Sequence` 着色器按 `_Sequence`（Rows(X) / Columns(Y) / FPS(Z) / TotalFrame(W)）播放，
  但 **fps 不在资产里**（运行时由代码传），所以插件默认按 30fps 拼 GIF，可用配置 `emoji_fps` 调
- 背景：默认**透明**（配置 `emoji_transparent`）。GIF 只支持单色透明，做法是把调色板最后一格
  留给透明、把 alpha<128 的像素涂掉；这些表情半透明像素只占 2.2%，二值化后看不出差别。
  关掉则铺白底——柔边完整，但会带一块白色方块，贴深色聊天底更显眼
- **静态表情**本身就是透明 PNG（`UT_Item_Emoji_*` 全是 RGBA，四角 alpha=0、边缘无白圈，全 438 张如此），插件原样发送不转码，所以不需要额外处理；只有在聊天里看到白框时才和客户端垫底有关

### 17.1 主界面三分法（2026-11-13 主人纠正）

对局主界面**不是一种**，按「能不能操作」分三种，识别结果写在 `screen`：

| screen | 界面 | 允许的操作 |
|---|---|---|
| `main_turn` | 角色操作页：可出牌、可开技能、可移动 | `card` `skill` `go` `skip` |
| `main_move` | 移动页：选岔路 / 停留 / 继续移动 | `go` `choose` `stop` |
| `main_watch` | 观战页：队友或别人的回合，只能看 | **什么都不做** |

弹窗盖在主界面上时按弹窗算（`relic_pick` / `relic_buy` / `shop_card` / `fight_*` / `assault_pick` / `dice_pick`）。

战斗里的三个出牌页要说清区别：

| screen | 含义 | 能干什么 |
|---|---|---|
| `fight_play_atk` | `fight.attacker.pid == selfPid` → **我是攻击方** | 出**攻击**牌、点确定 |
| `fight_play_def` | `fight.defender.pid == selfPid` → **我是防御方** | 出**防御**牌、点确定 |
| `fight_play` | 有攻防双方数据，但**自己不在其中**（`selfPid` 对不上） | 只点「确定 / 放过」，**不挑牌**（分不清攻守，怕拿错牌型） |

### 17.2 一条指令 = 一个界面的一件事（2026-11-13 主人口径）

| 指令 | 只在哪个界面 | 做什么 |
|---|---|---|
| `atk` | `fight_ask`（开战询问） | 点「攻击」 |
| `skip` | `fight_ask` | 点「放过」 |
| `skip` | `assault_pick`（突击页） | 点「取消」 |
| `skip` | `shop_card`（卡牌商店） | 点「取消」 |
| `skip` | `relic_buy`（筹码购买） | 点「取消」 |
| `def` | `fight_choice`（被攻击选择） | 点「防御」 |
| `dodge` | `fight_choice` | 点「闪避」 |
| `ok` | `fight_play_atk` / `fight_play_def` | 点 ready（确定） |
| `card` | `main_turn` / `fight_play_atk` / `fight_play_def` | 出牌 |
| `skill` | `main_turn` | 开技能 |
| `go` | `main_turn` / `main_move` | 移动 / 继续移动 |
| `choose` / `stop` | `main_move` | 选岔路 / 停下 |

两条硬规则：

1. **界面认不出来（`idle`）时一律放行** —— 识别不确定不该把陪玩整个停掉；
2. **明确认成别的界面就拦住**，并在失败回执里直说「现在在『观战页（别人回合，只能看）』」。

## 十八、经验怎么进决策（2026-11-14 定）

原则：**全自动靠规则，建议模式靠检索**。LLM/向量都不参与鼠标动作。

| 模式 | 决策来源 | 会不会用攻略 / 向量 |
|---|---|---|
| `/appa on` 全自动 | `pilot/autopilot.py` 固定评分 + 阈值（确定性、可复现） | **不用**。规则要能跑 60fps，容不得检索和 LLM 抖动 |
| `/appa off` 玩家自主 | 同上算建议 + **检索 `docs/攻略.md`** 附「相关经验」 | 用。BM25 关键词检索；配了 `embed_api` 再叠加向量余弦 |
| 半自动（单项授权） | 规则执行 + 建议卡同样附经验 | 用 |

### 18.1 写攻略 = 加决策经验（唯一的维护口子）

- `pkg/guide.py` 按 `##` / `###` / `####` **自动切块**，每块一条「经验卡」（标题 + 正文）
- 所以你只要在 `攻略.md` 里**按标题分节写**，下次渲染建议卡就能被检索到，不用改代码
- 小技巧：
  - 标题里写清「什么时候用」（如 `13.3 PVE 血线分层`），检索时标题权重也参与
  - 正文里写**具体数值和卡号**（`20005 遥控骰子`、`血量低于 1/3`），这些是关键词命中的关键
  - 别把多条互不相关的经验塞进同一节——切块是按标题切的，混着写会稀释命中

### 18.2 检索怎么做的

1. 查询 = 当前局势压成一句话：地图 + 阶段 + 事件标题/候选 + 血量档（满血/掉血/血量低）+ 角色号 + 是否战斗
2. BM25（纯 Python，零依赖）先排序
3. 配了 `embed_api` 再算向量余弦，按 `0.45×BM25 + 0.55×向量` 融合
4. 取 top3 贴在建议卡底部（标注 `bm25` / `hybrid`）
5. 向量接口挂了会自动冷却 5 分钟，期间只用 BM25，不会把建议卡拖慢

### 18.3 向量模型怎么配（可选）

面板 → 插件配置：

| 配置 | 说明 |
|---|---|
| `embed_api` | OpenAI 兼容的 `/embeddings` 地址。Ollama：`http://127.0.0.1:11434/v1`；百炼：`https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `embed_model` | 模型名，默认 `bge-m3`（中文长文本够用；轻量可 `bge-small-zh`） |
| `embed_key` | 云端才需要；本地 Ollama 留空 |

> 留空 = 只用 BM25。中文经验卡用 BM25 已经够准（实测「森秋幻境 石中剑」top1 命中 15.6、「血量低 回血」top1 命中 13.3）。

### 18.5 出牌经验的写法：血量 + buff + 怪位置一起看

单看「出了哪张牌」没有意义，必须带上当时的三个条件，经验才能复用。所以每条轨迹都记：

| 记录项 | 内容 |
|---|---|
| `hp_band` | `满血` / `带伤` / `低血`（≤1/3） |
| `buff_tags` | 从 buff 名归类：`atk`（强化/攻击/剑气）、`def`（护盾/格挡）、`heal`（回复/治疗）、`move`（疾行） |
| `scene.mons` | 每只怪的 `pid / hp / maxhp / node` |
| `scene.dist` | 我离**最近怪**几步（用地图 `nb` 邻接做 BFS） |
| `scene.mon_hp_min` | 最近那批怪里血量最低的（判断能不能一刀收掉） |

`tools/recap.py` 据此做两级归纳：

1. **局面指纹 → 选择**：同一组（血量档、buff、怪距离、怪血档）反复出现同一个选择 → 写成经验
   ```
   满血、atk、近格≤3 → 出《突刺》（attack）   3/3 次
   低血、无buff、近格≤3 → 出《遥控骰子》      2/2 次
   ```
2. **某张牌 → 共同场景**：这张牌被选的每一次，共同点是什么
   ```
   《突刺》的使用场景：血量=满血、buff=atk、怪距离=近格≤3
   ```

样本不够时自动放宽（全指纹 → 血+buff → 只血 → 只buff），不会因为凑不满 3 条就什么都不说。

### 18.4 两种经验来源

| 来源 | 谁写 | 存在哪 | 进的模式 |
|---|---|---|---|
| **人工经验** | 你 | `docs/攻略.md`（手写，按标题分节） | 建议卡检索 |
| **自动复盘经验** | `tools/recap.py` 从对局轨迹提炼 | `docs/攻略_自动经验.md`（带「待人工确认」标记） | 建议卡检索（确认后最好挪进攻略） |

自动复盘怎么跑：

```bash
# 1) 先有轨迹：引擎每次「轮到我 + 有明确动作」都会记一条（trace/YYYYMMDD.jsonl）
python tools/recap.py --days 1                 # 出复盘 markdown + 打印候选经验
python tools/recap.py --days 1 --emit          # 把候选经验追加进 docs/攻略_自动经验.md
python tools/recap.py --days 1 --emit --llm \
    --api http://127.0.0.1:11434/v1 --model qwen2.5:7b   # 让模型再提炼一轮（失败自动回落模板）
```

轨迹里每条记录了什么：当时局面（血量/金币/位置/手牌/阶段/地图）、**血量档 + buff 标签 + 怪物位置/距离/血量**、bot 的建议与理由、
以及**上一次决策之后发生了什么**（血量/金币/位置变化、手牌进出）。所以复盘能算「出这张牌之后到底赚没赚」。
